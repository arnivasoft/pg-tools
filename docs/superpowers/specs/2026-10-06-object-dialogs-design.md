# pg-tools — Alt Proje 5: Nesne Oluşturma / Düzenleme Diyalogları Tasarımı

- **Tarih:** 2026-10-06
- **Durum:** Plan 10–14 (View/MatView, Database, Role arka ucu dahil) uygulandı; Plan 15 (bu türlerin arayüzü) kalan
- **Kapsam:** Object Explorer'dan nesne **oluşturma, düzenleme, yeniden adlandırma, silme** (Schema, Sequence, Extension, Index, Table/Column/Constraint, View/Materialized View, Database, Role); önizlemeli, korumalı DDL uygulaması
- **Önceki alt projeler:** Object Explorer (Plan 1–4), Query Tool (5–6), Editör zekâsı (7), Dashboard (8–9) — hepsi `main`'de.
- **Teslim planları:** Plan 10 (arka uç çerçevesi + Schema, Sequence, Extension, Index) → Plan 11 (ön yüz çerçevesi + aynı dört tür) → Plan 12 (Table arka ucu: kolon/kısıt farkı) → Plan 13 (Table arayüzü) → Plan 14 (View/MatView, Database, Role arka ucu) → Plan 15 (View/MatView, Database, Role arayüzü).

---

## 1. Amaç ve bağlam

Object Explorer salt okunurdu; Query Tool SQL yazdırır ama nesne tanımlamak için DDL'i elle bilmek gerekir. pgAdmin'in "Create/Properties" diyaloglarının hafif karşılığı: alanları doldur, **üretilen SQL'i önizle**, onayla, uygula. Temel ilkeler: **hiçbir DDL önizlenmeden ve onaylanmadan çalışmaz**, üretim sunucularında yıkıcı değişiklik ek onay ister, kilitli sunucuda hiçbir değişiklik yapılamaz.

### 1.1 Kullanıcıdan gelen kararlar

| Konu | Karar |
|---|---|
| Nesne türleri | Tablo + kolon + kısıtlar; Index; Schema, Sequence, View/MatView; Database, Role, Extension |
| Teslim sırası | Çerçeve + basit nesneler → Tablo → Geri kalan (3 plan) |
| Uygulama | **SQL önizleme + onay**; isteğe bağlı "Query Tool'da aç" |
| Korumalar | Query Tool ile aynı: kilitli sunucuda tümü kapalı; üretimde yıkıcı işlemlerde sunucu adını yazarak onay; manuel transaction modu yok |
| Düzenleme | Mevcut tanım katalogdan yüklenir, **fark `ALTER …` olarak üretilir** |
| Alanlar | Her diyalogda **Sahip** ve **Yorum**; GRANT/REVOKE (yetki matrisi) sonraki iş |
| Giriş noktası | Sağ tık menüsü ve koleksiyonda "Oluştur…"; diyalog **sağ panelde ayrı sekme** (modal değil) |
| Teknoloji | Mevcut yığın (Rust, Tauri 2, SolidJS, Kobalte, Tailwind 4, CodeMirror 6) |

### 1.2 Başarı ölçütleri

| Ölçüt | Hedef |
|---|---|
| Güvenlik | Önizlenmemiş/onaylanmamış hiçbir DDL çalışmaz; kilitli sunucuda arka uç reddeder (yalnızca arayüz engeli yetmez) |
| Doğruluk | Her nesne türü için PG 10–18 matrisinde **gidiş-dönüş** testi: oluştur → katalogdan oku → tanım eşit; düzenle (fark) → uygula → katalog yeni tanıma eşit |
| Önizleme gecikmesi | Alan değişikliğinden sonra önizleme < 150 ms (saf Rust üretici, kısa debounce) |
| Ana paket | Diyalog kodu tembel parça; ana paket ≤ +3 KB |
| Sunucu yükü | Uygulama kısa ömürlü ayrı bağlantıda, `lock_timeout` ile; kuyrukta bekleyip kilit yığılması yaratmaz |

### 1.3 Kapsam dışı

- GRANT/REVOKE matrisi, varsayılan yetkiler (`ALTER DEFAULT PRIVILEGES`), RLS politikaları, trigger/fonksiyon/procedure/type/domain/FDW/publication/subscription diyalogları.
- Partition oluşturma/bağlama (tablo diyaloğu yalnızca partitioned tablo **tanımlar**), inheritance, EXCLUDE kısıtları, tablespace oluşturma.
- Kolon sırası değiştirme (PostgreSQL desteklemez; arayüz uyarır), toplu/şablonlu iş akışları, DDL geçmişi/geri alma.
- Rol üyeliklerinde PG 16+ seçenekleri (`INHERIT`/`SET` per grant): yalnızca salt okunur gösterilir (yükleyici doldurur, üretici yazmaz; yeni üyelik sunucu varsayılanlarıyla verilir).

## 2. Mimari

- Yeni crate **`pgt-ddl`** (`pgt-core` + `pgt-catalog` yardımcıları: `quote`, `PgVersion`, `VersionedSql`). Üç katman:
  1. **Model** (`model.rs`): nesne türü başına yapılandırılmış tanım (`SchemaDef`, `SequenceDef`, `IndexDef`, `TableDef { columns, constraints, … }`, …), `serde` + `ts-rs`. Arayüz formları bu tipleri düzenler.
  2. **Üretici** (`build/*.rs`): **saf işlevler**, ağ/IO yok. `create(def) -> Plan`, `alter(old, new) -> Plan`, `drop(target, options) -> Plan`, `rename(target, new_name) -> Plan`. `Plan { statements: Vec<Statement> }`, `Statement { sql, risk, transactional, note }` (bkz. §3). Sürüme duyarlı (`PgVersion`): ör. `INCLUDE` PG 11+, `GENERATED … STORED` PG 12+, `DROP DATABASE … WITH (FORCE)` PG 13+, ICU `locale_provider` PG 15+. Sürümün desteklemediği alan arayüzde gizlenir ve üreticide reddedilir.
  3. **Yükleyici** (`load/*.rs`, sürüm varyantlı `.sql`): havuzdaki **salt okunur** katalog bağlantısıyla (`ConnectionManager::run`) mevcut tanımı okur → `*Def`. Yükleyicinin döndürdüğü tanım, üreticinin `create` girdisiyle **aynı tip**tir (gidiş-dönüş testinin dayanağı).
- **Uygulayıcı** (`apply.rs`): her uygulama için **kısa ömürlü ayrı bağlantı** (`SessionProfile::Ddl`: `application_name = 'pg-tools ddl'`, `default_transaction_read_only = off`, `statement_timeout = 0`, `lock_timeout` çağrıdan (varsayılan 5 sn)). Transaction'a alınabilen ifadeler tek `BEGIN … COMMIT`; alınamayanlar (`CREATE INDEX CONCURRENTLY`, `CREATE/DROP DATABASE`, bazı `ALTER DATABASE`) **ayrı, sırayla** çalışır ve plan bunu açıkça işaretler. Hata → transaction `ROLLBACK`, hangi ifadenin (indeks + PG konumu) başarısız olduğu döner; transaction-dışı ifadelerden önceki kısmi uygulama kullanıcıya bildirilir. İptal desteklenir (`CancelHandle`).
- **Korumalar (arka uçta zorlanır):**
  - `ServerConfig.read_only_lock` → `ddl_apply` `locked` koduyla reddedilir (Query Tool'un `locked` kapısı gibi); `ddl_preview`/`ddl_load` serbesttir.
  - Plan'da en az bir `Destructive`/`DataLoss` ifade varsa `ddl_apply` `confirmed: true` ister (`confirmation_required`). Üretim ek onayı yalnızca **`DataLoss`** içeren planlar içindir: sunucu etiketi **üretim** ve plan `DataLoss` ise ek olarak `confirmed_production: true` (istemci sunucu adını yazmıştır) gerekir (`production_confirmation_required`); yalnızca `Destructive` plan üretimde de yalnız `confirmed` ister. Arka uç bayrakları yalnızca varlık olarak denetler, adın yazılması arayüz sorumluluğudur.
  - Arka uç ifadeleri istemciden **almaz**: istemci tanımı (`def`/`old`/`new`) gönderir, arka uç planı yeniden üretir ve uygular (istemcide üretilmiş/değiştirilmiş SQL çalıştırılamaz). Önizlenen planın özeti (`plan_hash`) uygulama isteğine eklenir; hash uyuşmazsa (sürüm/def değişti) `plan_changed` ile reddedilir.
- **Tauri komutları** (`ddl_*`, `Box::pin`, ts-rs bağlamaları): `ddl_load(node_id) → LoadedDef`, `ddl_preview(request) → PlanView`, `ddl_apply(request, lock_timeout_ms, confirmed, confirmed_production) → ApplyResult`, `ddl_cancel(apply_id)`, `ddl_lookups(kind, context) → Lookups` (açılır listeler: sahipler/roller, tablespace'ler, şemalar, tipler, extension'lar (`pg_available_extensions`), index yöntemleri, collation'lar, tablo kolonları, referans verilebilir tablolar).
- Günlük: **SQL metni, parola ve tanım değerleri günlüğe yazılmaz**; yalnızca nesne türü, ifade sayısı, süre, sonuç kodu.
- **Sözleşme notları (Plan 10 arka ucu, arayüz Plan 11 için):**
  - `PlanRequest::Alter` ve `PlanRequest::Drop` değiştirilen/silinen nesnenin `object: ObjectRef` kimliğini taşır; `ddl_apply` nesneyi yeniden yükler ve istemcinin `old`/`def` tanımının sunucudaki güncel tanıma **birebir** eşit olmasını ister (fark → `plan_changed`; yok/sistem nesnesi/identity dizisi hataları olduğu gibi geçer). `ddl_preview` bu denetimi yapmaz. Arayüz her zaman `ddl_load`'un döndürdüğü tanımı geri gönderir.
  - `SequenceDef`'in sayısal alanları (`increment`, `minValue`, `maxValue`, `start`, `cache`) JSON'da ondalık **dizge** olarak gider (JS `number` bigint aralığında kesinlik kaybeder); girişte dizge de tamsayı da kabul edilir. "Sayılar `number`" kuralının bilinçli tek istisnasıdır.
  - `FieldError.path` sözlüğü: alan adı (`name`, `schema`, `table`, `method`, `unique`, `include`, `tablespace`, `fillfactor`, `constraint`, `minValue`…), liste öğeleri `columns[i].key` / `columns[i].opclass` / `include[i]`, alter'da eski tanım `old.<alan>`, tür uyuşmazlığı `kind`.
  - Geçersiz tanım: `PlanView.empty = true` ve `errors` boş değil; `ddl_apply` `invalid_def` kodunu döndürür. Boş plan (değişiklik yok) uygulanmaz: kodsuz `invalid` ("Değişiklik yok").
  - Tablespace kaldırılamaz (yalnızca değiştirilebilir): varsayılana dönmek için `pg_default` açıkça seçilir.
  - `ApplyOutcome::Applied.created` yeni nesnenin kimliğini (en iyi çaba), `ApplyOutcome::Failed.position` PG hata konumunu (başarısız ifadenin metninde 1 tabanlı karakter sapması) taşır; `DdlTarget.refreshNodeId` uygulamadan sonra yenilenecek ağaç düğümüdür; yüklenen `IndexDef.valid` geçersiz (INVALID) indeksi işaretler.
  - İndeks yapısal değişikliği tek transaction'da `DROP INDEX` + `CREATE INDEX`'tir (tablo, işlem bitene kadar okuma/yazmaya kapalı kalır); kesintisiz yeniden kurma ileri bir plana ertelendi.
  - **Table arka ucu (Plan 12) sözleşme notları (arayüz Plan 13 için):** `ColumnDef.attnum` ve `ConstraintDef.oid` yalnızca yükleme kimliğidir (alter eşlemesi içindir; yeni satırda boş bırakılır, istemci üretmez). `ColumnDef.dataType` serbest SQL değil, katı dilbilgisiyle doğrulanan tip ifadesi metnidir (ör. `numeric(10,2)`, `public.mytype`, `int4[]`). `DdlTarget.focus` yalnızca kolon/kısıt düğümünde dolar (`column`/`constraint` + `id`); hedef yine tablo `object`'idir. **Odak koruması:** `focus` doluyken drop ve rename eylemleri reddedilir (kolon/kısıt düğümü hiçbir zaman DROP TABLE diyaloğu açmaz; `designer-open.ts` + test); Plan 13 bu korumayı korumalı, kolon/kısıt silme tablo diyaloğu içinden yapılır. Alter'da `ApplyOutcome::Applied.created` tablo için yeni (yeniden adlandırılmış/şeması değişmiş) tablo kimliğini taşır; kolon/kısıt eklemeleri ayrı `created` üretmez. Bölüm düğümleri Table olarak düzenlenebilir (`isPartition`: yalnızca yeniden adlandırma/şema/sahip/tablespace/yorum; kolon/kısıt değişikliği doğrulama hatası). `defaults(Table)` `columns = []` döndürür ve `create` en az bir kolon ister. Alter yalnızca değişen ya da ifadeye yazılan alanları doğrular (dokunulmamış yüklü tip/ad/ifade create dilbilgisine takılmaz); silinen kolona başvuran kalan CHECK ve desteklenmeyen kısıtlar için plan uyarısı verilir. Serbest SQL alanlarında sıradan `'…'` içinde `\` reddedilir (kaçış için `E'…'`; uygulayıcı her ifadeden önce, transaction dışı olanlar dahil, `standard_conforming_strings = on` kurar; regex CHECK'leri ve indeks koşullarında `\` gerekiyorsa `E'…'` kullanılmalıdır).
  - **Plan 13 notları (Table arayüzü):** Kolon/kısıt düğümleri yalnızca Düzenle sunar; tablo diyaloğu `column:<attnum>` / `constraint:<oid>` odağıyla açılır, sekme eşleme `findAlter` ile yapılır (tabs-store anahtarı değişmez). SQL önizleme ayrı bölüm sekmesi değil, sağ panelde (Plan 11 yerleşimi; Table için %38). Table formunun sekme çubuğu elle yazılmıştır (Table dosyalarında Kobalte yok): Kobalte'yi tembel formdan doğrudan içe aktarmak paylaşılan kodu başlangıçta yüklenen bir parçaya böler (başlangıç baytı artar); kural: `index.html` yalnızca solid/web/Icon parçalarını önyükler. Form düzeyinde `SelfSnap` izleyicisi (kendine-başvuran FK ve kolon yeniden adlandırma için konum anlık görüntüsü) ve `*Snap` sarmalayıcıları (`addConstraintSnap`, `removeConstraintSnap`, `restoreConstraintSnap`, `switchConstraintTypeSnap`, `withFkTargetSnap` → `pointFkAtSelf`/`pointFkAtOther`) tüm kısıt ekle/sil/geri al, tür değişimi ve FK hedef değişimlerinden geçer; tablo adı/şeması `renameTable(d, patch, snap)` ile yalnızca anlık görüntüdeki FK'lere yazılır; yazım sırasındaki ara adlar başka satırın başvurusunu çalmaz. PK üyelerinin NOT NULL'ını yalnızca editör zorlar (`reconcilePrimaryKeyNotNull`, her düzenlemeden sonra; zorlananlar kaydedilir ve kolon PK'dan çıkınca eski değerine döner). Bölüm tablosu / INHERITS çocuğunda düzenlenebilir: ad, şema, sahip, kalıcılık, tablespace, fillfactor, yorum ve kolon yorumları; kolon ve kısıt yapısı kilitlidir. Sürüm bağımlı alanlar (VIRTUAL, NULLS NOT DISTINCT, INCLUDE, HASH, UNLOGGED bölümlü create) arayüzde gizlenmez; ipucu + arka uç hatası (arayüz modelinde sunucu sürümü yok). Kimlik dizisi seçenekleri düzenlenmez ("Düzenlenmeyenler"). Ana paket telafisi: `t.query.export` → tembel `strings-export.ts`. **Backlog:** PG 18 NOT NULL kısıt nesneleri, bölümlenmiş tabloda alter kuralları, yalnızca collation değişiminde DataLoss sınıfı, silinen kolonu içeren indeks uyarısı, 63 bayttan uzun eski ad, yazılmamış 2 Docker testi, arka ucun LIST çok anahtarlı bölümlemeyi reddetmesi, indeks anahtarlı rozet/hata kayması (m-2; Kolonlar + Kısıtlar).
  - **View/MatView/Database/Role arka ucu (Plan 14) sözleşme notları (arayüz Plan 15 için):**
    - **Kapsam:** Database ve Role sunucu kapsamlıdır: `DdlTarget.databaseOid` bu türlerde `null`; arayüz `ddl_*` çağrılarında `databaseOid: null` gönderir (komutlar `Option<u32>`); Query Tool'da aç → bakım veritabanı. Veritabanı kapsamlı türlerde `null` → `invalid`. Yükleme ve uygulama aynı hedef kuralını kullanır.
    - **Hedefler:** `dbs` → create Database; `db:N` → object Database; `roles` → create Role; `role:N` → object Role; `…/views`, `…/view:N`, `…/matviews`, `…/mv:N` aynı kalıp; `refreshNodeId` koleksiyon. Görünüm/MV kolon düğümleri menü almaz. Sistem rolleri (`pg_*`) arka uçta `invalid`; menü bunları göstermemeli (`flags.system`).
    - **Parola:** `RoleDef.password` `"keep" | "set" | "clear"`; değer yalnızca `ApplyOptions.password` (`string | null`) — önizleme isteğine asla girmez; planda `redacted: true` ifade varken parola yoksa `role_password_missing` kodu, parola var ama gizlenmiş ifade yoksa kodsuz `invalid` ("Bu planda parola kullanılmıyor."); `redacted` ifade içeren plan Query Tool'a aktarılmamalı (metin bilerek çalıştırılamaz). Yükleme her zaman `"keep"`; eski tarafta `"keep"` dışı → `plan_changed`. Parola **istemcide SCRAM-SHA-256** ile özetlenir (düz metin sunucuya gitmez); başarısız parola ifadesinde `position` hep `null`. Geçersiz niyet değeri ayrıştırma hatası değeri yankılamaz.
    - **Drop:** `PlanRequest.drop.force` yalnızca Database (PG 13+); Database/Role için `cascade = true` alan hatası. `DROP DATABASE` DataLoss (üretimde ad yazma); `DROP ROLE` Destructive; görünüm/MV drop Destructive, CASCADE DataLoss.
    - **FieldError yolları:** View `schema|name|owner|query|checkOption|securityBarrier|securityInvoker|comment|recreate|old.*`; MatView `schema|name|owner|query|tablespace|fillfactor|withData|refresh|comment`; Database `name|owner|template|encoding|localeProvider|lcCollate|lcCtype|providerLocale|tablespace|connectionLimit|isTemplate|allowConnections|settings|settings[i].name|settings[i].value|comment|force|cascade`; Role `name|login|…|connectionLimit|validUntil|password|memberOf|memberOf[i].role|settings|settings[i].name|settings[i].value|comment|cascade`.
    - **Yükleme normalleştirmesi:** view/MV `query` `pg_get_viewdef` metnidir (biçim sunucunundur; boşluk değişikliği de "değişiklik"tir — MV'de yeniden kurma demektir, arayüz metni normalleştirmemeli); `columns`/`unsupported`/`inheritOption`/`setOption` salt okunurdur; Database `template = null`, create-only alanlar dolu ve alter'da kilitli; `tablespace` her zaman dolu; Role `validUntil` UTC `…Z` biçimi, temizlenemez (`infinity`); ayarlar ada göre sıralı. Create-only yerel ayar alanları sunucunun normalleştirdiği biçimde döner (glibc `POSIX` → `C`, ICU PG 16+ `en_US` → `en-US`); istemci kanonikleştirmez.
    - **Alter-only bayraklar:** `ViewDef.recreate` (yalnızca sorgu değişmişken anlamlı; DataLoss), `MatViewDef.refresh` (`withData` tablosuna uyar; Destructive). Yüklemede `false`/`null`; uygulama sonrası yeniden yüklemede sıfırlanır.
    - **Yeni lookup'lar:** `grantable_roles` (`pg_database_owner` hariç), `encodings`, `template_databases`, `locales{provider}`, `settings` (hepsi `databaseOid: null` ile çalışır).
    - **İfade sırası:** Database (transaction dışı, tek tek) ve View/MatView alter/yeniden kurmada `OWNER TO` **en sondadır** (PG 16+ INHERIT'siz role devirden sonra kalan ifadeler 42501 vermesin); MatView'de REFRESH bu yüzden eski sahip olarak çalışır.
    - **GUC adı kuralı:** noktasız (yerleşik) adlar yeni tarafta yalnızca küçük harf (`TimeZone` → "küçük harfle yazılmalı: 'timezone'"), yükleyici bunları ASCII küçük harfe katlar; **noktalı özel adlar yazımını korur** (`App.Mode`: yükleme ve yazma aynen; PG başka oturumda harfe duyarlı eşler), yinelenen ad denetimi ASCII harfe duyarsız; her ad parçası ≤ 63 bayt; değerde NUL/denetim/biçim-yön karakteri yok; doğrulama tam olarak yazılan girdileri kapsar.
    - **Eski taraf gevşek:** yüklü (eski) adlar/sahip/tablespace yalnızca kimlik kurallarıyla (boş/NUL/denetim, ayar adında boş parça yok) denetlenir; değişmeyen yüklü değer düzenlemeyi engellemez, yazılan her alan katı kuraldan geçer.
    - **`ApplyOutcome` ekleri (isteğe bağlı alanlar):** `applied.warnings?: string[]` — uygulama sonrası denetim (ör. PG 16+ GRANTED BY'sız `REVOKE` başka grantor'ın üyeliğini kaldırmadıysa üyelik farkı uyarısı); `failed.created?: ObjectRef` — kısmi uygulamada (transaction dışı, `committed > 0`; ör. CREATE DATABASE kalıcı, sonraki ayar başarısız) oluşturulan/yeniden adlandırılan nesne.
    - **Bakım veritabanı kapısı:** bakım veritabanı (kayıttaki ve oturumun bağlı olduğu ad) yeniden adlandırılamaz, taşınamaz, `ALLOW_CONNECTIONS false` ya da `CONNECTION LIMIT 0` yapılamaz, silinemez ve şablon olarak kopyalanamaz (kodsuz `invalid`, bağlantı açılmadan). Kendi havuz bağlantılarımız yeniden adlandırma/taşıma/silme ve CREATE DATABASE şablonu için bırakılır; başka oturumlar 55006 + ipucu (Query Tool/Dashboard, PG 13+ FORCE, kendi bağlantının yeniden bağlanmış olabileceği). Diğer kendini kilitleme durumları (bağlı rolü NOLOGIN/geçmiş VALID UNTIL yapmak, bakım veritabanında `default_transaction_read_only` vb.) Plan 15 uyarı backlog'undadır.
    - **PG 16+ üyelik grantor'ı:** önyükleme süper kullanıcısından başkasının verdiği ya da birden çok grantor'lu üyelik salt okunur `unsupported` girdisidir (`MEMBER r (grantor g)`, `MEMBER r (birden çok grantor)`); düzenlenmez, uygulama sonrası karşılaştırmada "var" sayılır.
    - **İpuçları:** 42P16/42804 yalnızca `CREATE OR REPLACE VIEW` (Karar 1 metni), 55000 yalnızca `REFRESH … CONCURRENTLY`, 55006 Database, 42501 genel yetki, 2BP01 Role / View-MatView; PG'nin kendi ipucu varsa korunur.
    - **`ApplyOutcome` ekleri (zorunlu tüketim):** `applied.warnings?: string[]` **gösterilmelidir** (uygulama başarılı olsa da sekmede kalıcı uyarı şeridi + toast'ta özet; ör. PG 16+ GRANTED BY'sız etkisiz `REVOKE` → üyelik farkı uyarısı). `failed.created?: ObjectRef` kısmi uygulamadır (ör. CREATE DATABASE kalıcı, sonraki SET/COMMENT başarısız; rol için de genel kural): arayüz oluşturulan nesneyi **açmayı/yenilemeyi önermeli**, ağacı yenilemeli ve aynı create'i **körlemesine yeniden denetmemelidir** (aynı plan 42P04/42710 ile düşer) — create sekmesi bu nesnenin düzenleme sekmesine dönüştürülür ya da Uygula kapatılıp "Düzenle olarak aç" sunulur.
    - **Kendini kilitleme uyarıları (istemci, hata değil):** düzenlenen rol bağlı kullanıcının kendisiyse (sunucu kaydındaki kullanıcı adı) `login` kapatma, `connectionLimit = 0`, geçmiş `validUntil` ve kendi parolasını değiştirme (kayıtlı parola eskir; yeniden bağlanmada istenir) uyarıları; bakım veritabanı ret iletileri arka uçtan gelir.
    - **Yerel ayar normalleştirmesi:** create-only alanlar sunucunun biçiminde döner (glibc `POSIX` → `C`, PG 16+ ICU `en_US` → `en-US`); Database formu alter'da salt okunur alanların yanında bu notu gösterir, istemci kanonikleştirmez.
    - **İpucu metinleri:** 42501 ipucu arka uçtan gelir ("Bağlı rolün yetkisi yetmiyor; SUPERUSER/REPLICATION/BYPASSRLS yalnızca süper kullanıcı verebilir, sahip değiştirmek için…"); arayüz kendi metnini üretmez, `errorText` + `hint` yolu yeter. 2BP01 yeniden kurmada CASCADE önermez.
    - **Menü:** `pg_*` (önceden tanımlı) roller için designer eylemi yok (`flags.system`); arka uç zaten `invalid` döner.
    - **VALID UNTIL:** saat dilimi yardımı (yerel saat girilir, UTC `…Z` olarak saklanır ve öyle gösterilir; "Süresiz" = `infinity`, temizleme yok).
    - **Ayar adları:** `search_path`/`temp_tablespaces` öğelerinde tırnaksız büyük harfli öğe (`MySchema`) sunucuda `"MySchema"` anlamına gelir → ön uyarı; noktasız ad yalnızca küçük harf, noktalı özel ad yazımını korur (`App.Mode`), yalnızca harf büyüklüğü değişen özel ad için arka uç plan uyarısı verir.
    - **Gizlenmiş ifadeler:** `redacted: true` ifade içeren plan Query Tool'a **açılmaz ve kopyalanmaz** (kopya/aç düğmeleri kapalı + gerekçe); parola değeri denetleyicide tepkisel olmayan haritada tutulur, yalnızca `ddl_apply`'da gider; uygulama kapısı (`password`) iki girdi eşleşmeden Uygula'yı kapatır.
    - **Backlog:** noktalı özel ayarın yalnızca harf büyüklüğü değişimi PG'de güvenilir uygulanmaz (`RESET` başka oturumda yer tutucu oluşturup eşleşmeyebilir; üretici uyarı verir, hata değil); Table/Sequence/Schema/Index için de `OWNER TO` en sonda; `load_table.sql` tablespace `pg_default` süzgeci (MatView'deki `reltablespace = 0` kuralı); spec "SQL editörü" ile Plan 15 metin alanı farkı; view/MV kolon yeniden adlandırma/yorum, MV indekslerinin yeniden kurmada otomatik oluşturulması, `CREATE DATABASE … STRATEGY/OID/ICU_RULES`, `ALTER ROLE … IN DATABASE … SET`, rol üyeleri (ters yön), `REASSIGN/DROP OWNED`, GRANT matrisi; serbest bırakma ile yeniden bağlanma yarışı (G-6: yeniden deneme ipucu var).

## 3. Plan ve risk modeli

`Statement.risk`:

| Risk | Örnek | Onay |
|---|---|---|
| `Safe` | `CREATE …`, nullable `ADD COLUMN`, `RENAME`, `COMMENT ON`, `ALTER … SET DEFAULT` | Yalnızca "Uygula" |
| `Destructive` | `DROP …` (schema/index/sequence/view/materialized view/role/extension), `DROP CONSTRAINT`, `ALTER … SET NOT NULL` (mevcut veriyle başarısız olabilir → uyarı; veri kaybetmez), `ALTER TABLE … SET UNLOGGED`, `REFRESH MATERIALIZED VIEW` (her biçim), rol üyeliği `REVOKE` / `REVOKE ADMIN OPTION FOR` (yetki kaybı) | Onay kutusu ("Etkisini anladım") |
| `DataLoss` | `DROP TABLE` (CASCADE'siz de: tüm satırlar gider), `DROP DATABASE [WITH (FORCE)]` (Plan 14 Karar 3), `DROP COLUMN`, `ALTER COLUMN TYPE`, `DROP … CASCADE`; **düzenlemede yeniden kurma** (view `recreate` → `DROP VIEW` + `CREATE VIEW`, MatView tanım değişikliği → `DROP MATERIALIZED VIEW` + `CREATE …`: yetkiler, INSTEAD OF tetikleyicileri/kurallar, MV verisi ve indeksleri kaybolur; Karar 2) | Onay kutusu + **üretimde sunucu adını yazma** |

Plan görünümü (`PlanView`): ifade listesi (sıra numarası, SQL, risk rozeti, `transactional` bayrağı, not), uyarılar (ör. "Kolon sırası değiştirilemez", "Tür dönüşümü `USING` gerektirir", "Veritabanı yeniden adlandırma için açık oturum olmamalı"), `plan_hash`, toplam risk. Boş plan (değişiklik yok) `Uygula`yı kapatır.

## 4. Arayüz

- **Sekme türü** `designer` (`tabs-store` kalıbıyla; dashboard gibi tembel parça, `DesignerTabs`/`DesignerView` ana pakete ince kancayla bağlanır). Başlık: `Oluştur: Table · <sunucu>/<db>` / `Düzenle: <nesne>`. Sekme kapanırken kaydedilmemiş değişiklik varsa onay sorar.
- **Giriş noktaları** (`ExplorerMenu`/`actions.ts`): koleksiyon düğümünde **Oluştur…**; nesne düğümünde **Düzenle…**, **Yeniden adlandır…**, **Sil…**. Kilitli sunucuda değiştiren eylemler devre dışı + gerekçe (`title`). Eylem kümeleri `actionsFor` içinde türe göre.
- **Yerleşim:** solda form (bölüm sekmeleri: Genel, tür özel, "SQL" önizleme), sağda/altta **canlı SQL önizleme** (salt okunur CodeMirror, `DdlView` ile aynı kurulum; hata veren ifade vurgulanır); altta **uygulama çubuğu**: risk özeti, `lock_timeout` seçici (1 sn / 5 sn / 30 sn / sınırsız), **Uygula**, **Query Tool'da aç**, **Vazgeç**.
- **Önizleme akışı:** form değişir → 150 ms debounce → `ddl_preview` (en son istek kazanır) → plan görünür. Doğrulama hataları (boş ad, 63 bayt aşımı, aynı kolon adı, eksik zorunlu alan) form üzerinde alan altında; geçersiz formda önizleme "formu tamamlayın" der ve Uygula kapalıdır.
- **Uygulama sonrası:** başarı toast'ı; Explorer'da ilgili düğüm yenilenir (oluşturma → üst koleksiyon; düzenleme → düğüm; silme → düğüm kaldırılır); düzenleme sekmesi yeni tanımı yeniden yükler. Hata: PG'nin `message`/`detail`/`hint` metni + başarısız ifadenin vurgulanması; form korunur.
- **Silme** ayrı küçük diyalogtur (sekme açmaz): nesne adı, `CASCADE` onay kutusu (varsayılan kapalı), plan önizleme, risk onayı. `CASCADE` kapalıyken PG bağımlılık hatası verirse `detail` (bağımlı nesneler) gösterilir.
- **Erişilebilirlik / tutarlılık:** Kobalte bileşenleri, tüm alanlarda etiket, hata alanları `aria-describedby`, odak sırası; Türkçe metinler `strings-designer.ts` (yalnızca tembel parçada).

## 5. Nesne türleri (ilk sürüm alanları)

Her türde ortak: **Ad, Sahip (rol listesi), Yorum**; düzenlemede **Yeniden adlandır**.

- **Schema:** ad, sahip, yorum. Sil (`DROP SCHEMA [CASCADE]`).
- **Sequence:** şema, veri tipi (smallint/integer/bigint, PG10+), artış, min, maks, başlangıç, cache, döngü, `OWNED BY tablo.kolon`; düzenleme: `ALTER SEQUENCE` farkı + `RESTART` seçeneği.
- **Extension:** `pg_available_extensions`'tan seçim, şema, sürüm, `CASCADE`; düzenleme: `ALTER EXTENSION … UPDATE TO`, `SET SCHEMA`; sil.
- **Index:** tablo, ad, yöntem (btree/hash/gist/gin/brin/spgist), kolon/ifade listesi (opclass, collation, sıralama, NULLS), `INCLUDE` (PG11+), `UNIQUE`, `WHERE`, tablespace, `fillfactor`, `CONCURRENTLY` (transaction dışı, uyarılı); düzenleme: yeniden adlandır, tablespace, `fillfactor`; **tanım değişikliği drop + create olarak planlanır ve bu açıkça not edilir**; `REINDEX` eylemi.
- **Table (Plan 12 arka uç / Plan 13 arayüz):** şema, ad, sahip, tablespace, `UNLOGGED`, `WITH (fillfactor …)`, partitioned (`RANGE`/`LIST`/`HASH` anahtarları; yalnızca oluşturmada); kolonlar (ad, tip + uzunluk/hassasiyet/dizi, NOT NULL, default, identity (`ALWAYS`/`BY DEFAULT` + sequence seçenekleri), `GENERATED … STORED` (PG12+), collation, yorum); kısıtlar: **PK, UNIQUE, CHECK, FK** (hedef tablo/kolonlar, `MATCH`, `ON UPDATE/DELETE`, `DEFERRABLE`, `NOT VALID`); düzenleme farkı: ad değişikliği, kolon ekle/sil/yeniden adlandır, `ALTER COLUMN TYPE … USING` (kullanıcı ifadesi), NOT NULL/default/identity aç-kapa, kısıt ekle/sil/yeniden adlandır/`VALIDATE`; kolon sırası değişikliği uyarı.
- **View / Materialized View (Plan 14):** şema, ad, sahip, sorgu gövdesi (SQL editörü; Plan 14 sözleşmesi metin alanı öngörür, bkz. sözleşme notları), seçenekler (`security_barrier`, `check_option`, PG 15+ `security_invoker`), MatView: `WITH [NO] DATA`, tablespace, fillfactor; düzenleme: `CREATE OR REPLACE VIEW` — kolon uyumsuzluğunda PG reddeder (42P16) ve kullanıcı açıkça "Yeniden oluştur (DROP + CREATE)" seçer (Karar 1; otomatik yükseltme yok), yeniden adlandır, MatView `REFRESH` (Destructive) ve tanım değişikliğinde yeniden kurma (DataLoss).
- **Database (Plan 14):** ad, sahip, template, encoding, locale/collation (PG15+ ICU sağlayıcısı), tablespace, bağlantı limiti, `is_template`, `allow_connections`; düzenleme: yeniden adlandır (açık oturum uyarısı), sahip, tablespace, limit, bayraklar; sil (`WITH (FORCE)` PG13+ onay kutusu). **Tüm ifadeler transaction dışı.** Dashboard'daki oturum sonlandırmaya bağlantı noktası (ilgili uyarı metninde ipucu).
- **Role (Plan 14):** ad, `LOGIN`, `SUPERUSER`, `CREATEDB`, `CREATEROLE`, `REPLICATION`, `BYPASSRLS`, `INHERIT`, bağlantı limiti, `VALID UNTIL`, **parola (yalnızca yazılır, asla yüklenmez/gösterilmez)**, üyelikler (`GRANT rol TO rol` ekle/çıkar). **Parola önizlemede `********` (tırnaksız) olarak maskelenir**; uygulamada girilen değer kullanılır, günlüğe/hata iletisine/geçmişe girmez. Parola **istemcide SCRAM-SHA-256 ile özetlenir** (psql `\password` gibi; Plan 14 inceleme M-1, önceki "düz metin gönderilir" kararının yerine): sunucuya, `log_statement`/`pg_stat_statements` kayıtlarına yalnızca doğrulayıcı düşebilir, düz metin asla. Tur sayısı 4096 sabittir (PG 16+ `scram_iterations` dikkate alınmaz).

## 6. Güvenlik ve gizlilik

- Önizleme/yükleme **salt okunur** havuz bağlantısından; yazan yol yalnızca `ddl_apply` (ayrı bağlantı, ayrı profil, kilit kapısı).
- Arka uç istemci SQL'i çalıştırmaz (§2): SQL enjeksiyonu yüzeyi, `quote` ile tırnaklanan tanımlayıcılar ve `quote_literal` ile bağlanan değerlerden ibarettir; **tüm tanımlayıcı/değer yerleştirmeleri tek bir yardımcıdan** geçer ve birim + özellik tabanlı testlerle (rastgele/Unicode/tırnaklı adlar) doğrulanır. Serbest SQL alanları (view gövdesi, CHECK/default/WHERE ifadesi, `USING`) kullanıcı SQL'idir ve **olduğu gibi** yerleştirilir; bu alanlar için arayüz "ifade, SQL olarak çalıştırılır" notunu gösterir ve sunucu tarafında ayrıştırılarak hatası önizlemede (`PREPARE`/Parse yoluyla, Query Tool'daki `guarded_parse` kalıbıyla; uygulama öncesi **çalıştırmadan**) gösterilebilir.
- Parola, SQL metni ve tanım içeriği günlüğe, hata iletisine, `localStorage`'a, geçmişe yazılmaz.
- Kilit: arka uç zorlar; etiket/üretim onayı bayrakları arka uçta varlık olarak denetlenir.

## 7. Test stratejisi

- **Üretici (Rust, saf):** tablo odaklı birim testleri + `insta` anlık görüntüleri (nesne türü × sürüm), tırnaklama özellik testleri (Unicode, çift tırnak, 63 bayt sınırı, ayrılmış sözcükler), fark üretimi (eski/yeni → beklenen ifade dizisi, no-op → boş plan, yeniden adlandırma + değişiklik birleşimi, sürüm kapıları).
- **Gidiş-dönüş (Docker, PG 10–18 matrisi, `scripts/test-matrix.ps1`):** her tür için `create(def)` uygula → `load` → `def` eşit; `alter(old,new)` uygula → `load` → `new` eşit; yıkıcı planlar (drop/type değişimi) ve geri alma (hata ortası → hiçbir değişiklik yok); transaction dışı ifadeler (`CONCURRENTLY`, `CREATE DATABASE`); `lock_timeout` (kilit tutan oturumla): uygulama zaman aşımıyla düşer ve sorguyu kuyrukta bırakmaz; kilitli sunucuda `locked`; onaysız yıkıcı plan `confirmation_required`; değişen `plan_hash` `plan_changed`; yetkisiz rol (42501) hatası aktarımı; parola günlüğe girmez (günlük yakalama testi).
- **Ön yüz (vitest, saf):** form modelleri (kolon/kısıt liste işlemleri, doğrulama kuralları, bağımlı alan gizleme sürüme göre), önizleme debouncer'ı (en son istek kazanır, kapanan sekme yanıtı yok sayılır), risk onayı modeli (hangi planda hangi onay), sekme yaşam döngüsü (kaydedilmemiş değişiklik uyarısı), Explorer yenileme kararı.
- **Ölçüm/elle:** ana paket boyutu aynı eşik; elle kontrol listesi `docs/smoke-test.md`'ye eklenir.
